## 1. どんなゲームか

白と黒の2色、「タマ（丸）」と「ウツワ（四角）」の2つの形でできた、2個1組で落ちてくる落ち物パズル（ぷよぷよ風）。

原則は3つ。
1. 同じ色・同じ形を上下左右に4個以上つなげると消える
2. 同じ色のタマとウツワが縦に重なると「カミ」になる（2026-10-24からの試作ルール）
3. 色違いのカミ同士が上下左右で触れると、中心＋上下左右1マスの十字範囲で爆発する。十字内のカミだけが次々に誘爆し、斜めには消去も誘爆も届かない（2026-10-24からの試作ルール）

詳しい仕様は同じフォルダの [SPEC.md](SPEC.md) を参照（ユーザーが書いた制作仕様書）。
コード内のコメント `spec #40` などは、この仕様書の項目番号を指している。

## 5. コードの構成（`__lua__` 内、`-->8` でタブ区切り）

| タブ | 内容 |
|---|---|
| 0 | 定数（盤面 8×14、1マス8px、ピースID 0〜6）、グローバル変数、落下速度、`_init` / `init_board` |
| 1 | ピースの判定用関数: `piece_color` `is_tama` `is_utsuwa` `is_kami` `can_form_kami` `make_kami` `valid_pair` |
| 2 | 落下中のピース: ペア生成（禁止ペアは引き直し）、出現、移動、回転＋壁蹴り（その場→左1→右1）、ハードドロップ、盤面への固定 |
| 3 | 盤面の処理: 重力、カミ化、4個消し判定、カミ爆発、得点、連鎖。**コルーチン `resolve_board_co`** で1段ずつフレームをまたいで見せる |
| 4 | `_update60`（入力・落下）、演出キュー、`_draw`、スプライト番号表 |

ピースID: `0`空 / `1`白タマ / `2`黒タマ / `3`白ウツワ / `4`黒ウツワ / `5`白カミ / `6`黒カミ

スプライトシート:
- 0〜3, 16〜19: 「CHAIN」文字（32×16）
- 4〜7, 20〜23: 「KAMI」文字（32×16）
- 8〜11: 通常ピース4種（白タマ, 黒タマ, 白ウツワ, 黒ウツワ）
- 12〜15: 白カミの4コマアニメーション
- 28〜31: 黒カミの4コマアニメーション

カミは`KAMI_ANIM_SPEED`=8フレームごとに4枚を切り替え、32フレーム周期でループする。

効果音（`sfx(n)`）: 0移動 / 1回転 / 2着地 / 3ハードドロップ / 4通常消去 / 5カミ化 / 6カミ爆発 / 7〜9連鎖（2連鎖 / 3〜4連鎖 / 5連鎖以上）/ 10ゲームオーバー / 20起動時（`_init` でチャンネル3）

カミ爆発時は`blast_phase`で14フレームの衝撃停止と18フレームの余韻を描画し、SFX 6をチャンネル0・1へ2フレームずらして重ねる。爆発判定は中心＋上下左右1マスの十字5マス。

## 7. 仕様書と違うところ / 気づいた点

仕様書の「仮案」を、プレイしてみて変えた可能性がある部分も含まれる。**ユーザーに確認せずに仕様書どおりへ戻さないこと。**

1. **得点の大きさ**: 仕様は「4個消し100点（+1個ごとに+50）、カミ起爆500点（誘爆1個ごとに+500）」。コードは `10 + 10*(n-4)` と `50 + 50*(誘爆数)` で、ほぼ1/10になっている。PICO-8の数値は約±32767が上限で、超えると値が回り込んで（オーバーフロー）おかしくなるため、小さくした可能性が高い。
2. **CHAIN倍率**: 仕様は後半ほど急に上がる案（×1, 2, 3, 5, 8）。コードは単純に ×連鎖数（`chain_mult`。コメントに「意図して一律にした」とある）。
3. **KAMI倍率は未実装**: 仕様33の「カミ爆発の点 × CHAIN倍率 × KAMI倍率」のうち、KAMI倍率の表がない。今は誘爆数を基礎点に足しているだけ。
4. **演出の強弱**: 仕様34の「連鎖が進むほど速く高く」「KAMIが大きいほど重く派手に」は一部だけ（連鎖SEが3段階、揺れの強さがカミ数に比例）。
5. **ロックディレイ（着地してから固定されるまでの猶予）なし**: 着地した次の落下タイミングで即固定。仕様44で「未確定」とされている項目。
6. **小さな不具合の候補**: ゲームオーバーからやり直すとき `fall_timer` `move_timer` `prev_left` `prev_right` が初期化されない。また、やり直しの処理が `_init` とほぼ重複している（`_init()` を呼べばまとめられるが、起動音 `sfx(20)` も鳴るようになる点に注意）。
7. **数値の上限に注意**: 掛け算・足し算は `safe_mul` / `safe_add` で上限を先に確認している。得点まわりを変えるときもこれを使う。
8. **`btnp()` は使わない（左右移動）**: PICO-8の `btnp()` は押しっぱなし15フレーム後に勝手に連打扱いになり、自前の連続移動と衝突する。左右は `btn()` の押した瞬間を自分で検出している。

## 11. 実験ルール 2026-10-24

友人の初見プレイでルールが直感的に伝わりにくかったため、色と方向の一貫性を上げる試作を開始した。通常の4個消しは残す。

- カミ化を「異色のタマ＋ウツワ」から「同色のタマ＋ウツワ」へ変更。
- 落下ペアから直接カミが生まれない思想は維持し、同色のタマ＋ウツワは落下ペア抽選から除外する。
- カミ爆発の消去範囲を3×3から、中心＋上下左右1マスの十字5マスへ変更。
- カミの誘爆も上下左右1マスだけ。斜めのカミは誘爆せず、斜めの通常ピースも消えない。
- 初回の起爆条件は従来どおり、異色のカミ同士が上下左右で接触すること。
- 得点式、爆発演出、通常4個消しの条件は今回は変更していない。

狙いは「同色でカミを作り、異色のカミをぶつける」「判定方向は上下左右」という覚えやすい構造にすること。プレイ後、十字爆発が弱すぎないか、同色カミ化が通常4個消しと競合して分かりにくくないかを確認する。

### 落下速度とせり上がり案

- じっくり連鎖を組めるよう、10組設置ごとの落下速度上昇（56→最速12フレーム）を停止した。
- 自然落下はゲーム中ずっと56フレームごと。ソフトドロップ4フレーム、ハードドロップ即固定は従来どおり。
- 12組のペアを置くごとに、空白なしのランダムな通常ピース8個の一段が下からせり上がる。当初の8組ごとでは連鎖作りを邪魔しやすかったため間隔を広げた。
- 一段すべてを無属性ブロックにする案は、ゲームの中心が連鎖作りから障害物処理へ偏ったため撤回した。
- せり上がりは、その手で起きた落下・消去・連鎖がすべて終わってから開始する。短い上昇アニメーション後、せり上がりで生じたカミ化・消去・連鎖も通常どおり解決する。
- 次の段の内容や残り手数は表示しない。せり上がる時点で最上段にピースがあればゲームオーバー。
